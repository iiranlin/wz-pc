# 发货附件调整：页面入口与手动验证

## 字段与存储

| 展示名称 | 主单 fileByList 键 | 上传要求 |
| --- | --- | --- |
| 装车照片1(车牌) | zczp（沿用旧字段） | 发货必填 |
| 装车照片2(车尾) | zczp2 | 发货必填 |
| 装车照片3(货位) | zczp3 | 发货必填 |
| 合格证 | hgz | 发货、入库质量附件上传时必填 |
| 自检报告 | zjbg | 发货、入库质量附件上传时必填 |
| 型式实验报告 | xssybg | 发货、入库质量附件上传时必填 |
| 其他质量文件 | zlzmwj（发货）、zlzm（入库） | 非必填 |

文案沿用需求中的“型式实验报告”。物资明细自己的 hgz、cjbg 保持独立，不与主单附件合并。
旧装车照片显示到照片1；旧质量文件显示到其他质量文件。读取时兼容 zlzmwj、zlzm，优先使用当前业务原字段。

## 页面地址及入口

地址中的 id、planId、batch 等必须取对应真实单据，不能混用需求计划、发货、收货、入库的 ID。以下路径接在当前系统域名后；如果部署使用 hash 路由，按现有地址形式拼接。

| 验证页面 | 页面地址或路由名称 | 从哪里进入 |
| --- | --- | --- |
| 新增发货 | `/scm/addSend?type=create&id=需求计划ID&planId=需求计划ID`，路由 `addSend` | 供应需求列表 → 选择需求 → 发货 |
| 编辑发货 | `/scm/addSend?type=update&id=发货ID&planId=计划ID&status=当前状态` | 发货列表 → 选择未发货单据 → 修改 |
| 货运中修改附件 | `/scm/addSend?type=view&id=发货ID&planId=计划ID&status=2` | 发货列表 → 选择货运中单据 → 修改 |
| 发货详情 | `/scm/addSend?type=view&id=发货ID`，路由 `addSend` | 发货列表 → 点击发货单号；供应商退货列表 → 点击发货单号 |
| 收货侧货运详情 | 路由 `addSendCy`，参数 `id=发货ID&type=view` | 收货列表、收货退货列表 → 点击发货单号；工作台关联货运单据入口 |
| 收货操作 | `/receive/receivePage?type=create&id=对应单据ID&supplyId=供应ID&takeStatus=收货状态`，路由 `receivePage` | 收货列表 → 选择未收货单据 → 收货 |
| 收货详情 | `/receive/receivePage?type=view&id=对应单据ID&takeStatus=收货状态` | 收货列表 → 点击收货单号 |
| 入库侧收货详情 | 路由 `receivePageCrk`，参数 `id=对应单据ID&type=view&takeStatus=收货状态` | 入库列表 → 点击收货单号 |
| 供应侧物流详情 | 路由 `logisticsView_scm`，参数 `id=计划ID&type=view`，可带 `batch=发货单号` | 供应需求列表 → 物流；发货列表 → 物流 |
| 收货侧物流详情 | 路由 `logisticsView_receive`，参数 `id=计划ID&type=view&batch=发货单号` | 收货列表 → 物流 |
| 入库/质检操作和详情 | `/wms/imPage?type=view&id=对应单据ID&storeStatus=入库状态&from=list`，路由 `imPage` | 入库列表 → 点击入库单号；或选择记录进入质检操作 |
| 入库旧版详情组件 | `src/views/production/wms/imList/components/detail.vue`，具体地址以后台菜单绑定为准 | 已同步组件；仓库未找到直接跳转该组件的固定路由 |
| 供应商退货详情（质量分支） | 路由 `returnDetail_gys`，参数 `id=退货ID&type=view`，其余参数由列表带入 | 供应商退货列表 → 退货单详情，选择质检退货记录；收货退货分支原本显示其他资料，保持该分支行为 |
| 入库退货详情 | 路由 `returnDetail_im`，参数 `id=退货ID&type=view` | 入库退货列表 → 退货单详情（非抽检分支） |
| 档案查询详情 | 路由 `archiveQueryDetail`，参数 `id=档案ID&type=view` | 档案查询列表 → 查看详情 → 发货等附件表格 |
| 项目档案查询详情 | 路由 `detailProjectArchive`，参数 `id=档案ID&projectId=项目ID&type=view` | 项目档案查询列表 → 查看详情 → 附件表格 |

除上面已由源码确认的三个路径外，其他路由由后台菜单接口动态下发，仓库没有固定 path，不能直接用路由名称冒充 URL。请按表中入口打开后复制地址栏，即可取得当前环境实际地址。`addSendCy`、`receivePageCrk` 是否复用本次更新的组件，也需在当前环境菜单绑定中验证。

## 手动验证顺序

1. 新增发货：确认三个照片字段顺序正确，随后是合格证、自检报告、型式实验报告、其他质量文件；逐个缺少六个必填附件之一时，保存应被拦截。
2. 六个必填项全部上传，其他质量文件留空：应可保存。分别上传 PDF、JPG、PNG，检查预览及照片转 PDF 行为。
3. 保存后重新打开编辑和发货详情，检查七组附件分别回显；不得串到物资明细的合格证、厂检报告。
4. 货运中进入修改，确认附件仍可编辑。删除其他质量文件后保存、重新进入，应保持为空；替换必填附件后重新打开，应显示新文件。
5. 按上表逐一进入收货、物流、入库、退货和两个档案查询页面，确认新增附件可见、名称正确、预览可用。物流有多批次时切换批次，确保不会残留上一批附件。
6. 历史单据只有旧照片和旧质量文件：旧照片应显示为照片1，旧质量文件应显示为其他质量文件，新增项为空；纯查看不应强制补传。进入可编辑发货保存时，需要补齐新增必填附件。
7. 入库质量附件可编辑场景：三个质量附件应必填，其他质量文件可不传；保存并重新打开检查回显。
8. 在浏览器网络面板核对提交及各详情接口返回的 fileByList，确认 zczp2、zczp3、hgz、zjbg、xssybg 被后端保留并向下游传递。前端已读写这些键；如果下游接口过滤新增键或档案接口不返回新增 fileType，需要后端同步支持。
